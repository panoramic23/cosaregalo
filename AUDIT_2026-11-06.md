# CosaRegalo — verifica tecnica e funzionale
**Data:** 6 novembre 2026 · **Ambiente:** SiteGround GoGeek / Node.js 22 · **Repository:** panoramic23/cosaregalo, main

Questa verifica riguarda il codice del repository e i collegamenti statici del pacchetto V6. **Non sostituisce un collaudo grafico o funzionale in browser sul dominio SiteGround**, che non risulta accessibile dal sistema di verifica esterno.

## Correzioni pubblicate
- **Footer:** rimosso da tutti i file HTML pubblici il collegamento a *Piano editoriale*; introdotto *Amministrazione* verso `/admin/` e allineati Privacy policy, Cookie policy, preferenze cookie e Powered by Panoramic.
- **Header:** eliminato il richiamo a *Scopri il nostro metodo · Come funziona*. Migliorate le regole CSS per centratura della ricerca e distanza tra le icone Instagram, TikTok e Pinterest.
- **Homepage:** rimossa la fascia ridondante di filtri, sostituita con quattro box categoria cliccabili. I filtri completi restano nella pagina *Trova un regalo*.
- **Ricerca:** risolto un errore JavaScript di dichiarazione duplicata che impediva l'inizializzazione dello script `assets/site.js`. La pagina supporta testo, categoria, budget, età, festa/ricorrenza, occasione e reset.
- **Leggibilità:** aggiornato il sistema tipografico e rimosso lo sfondo giallo dai pannelli editoriali (giallo riservato a bottoni, CTA, offerte).
- **Prodotti:** `api/catalog.mjs` richiede 6 prodotti per ciascuno dei 24 sottogruppi. I risultati reali dipendono da Amazon Creators API e dalla disponibilità dei prodotti; non vengono inventati prezzi.
- **Preview:** eliminati i banner dimostrativi e le diciture generiche di anteprima dalle pagine sorgenti. Restano dichiarazioni trasparenti quando un modello è solo un suggerimento editoriale.
- **Analytics:** corretta la raccolta di impressioni prodotti al consenso: nessuna impressione viene considerata come già tracciata prima dell'opt-in.
- **Sicurezza admin:** rimosso il calendario editoriale incorporato in chiaro nel codice HTML dell'area riservata; l'API admin continua a richiedere token server-side.
- **SEO:** il server risponde a `/robots.txt`; staging non indicizzabile finché non si abilita esplicitamente `SITE_INDEXABLE=true` sul dominio ufficiale. `/sitemap.xml` e `/ads.txt` vengono esposti solo con configurazione valida.
- **Social e ads:** icone social e posizioni AdSense/CJ predisposte; pubblicità disattivata fino a consenso e configurazione.

## Verifiche eseguite
- Controllo sintattico di `assets/site.js`, `assets/analytics.js`, `assets/ads.js` e `assets/admin.js`.
- Controllo sintattico del server Node.js dopo le modifiche, previa neutralizzazione degli import durante il parsing isolato.
- Pacchetto V6 originario: **25 file HTML**, **zero link locali e zero ancore interne mancanti** nel controllo di struttura del pacchetto. Questo test è una verifica statica sul pacchetto, non su ogni risposta HTTP SiteGround.
- Verificata via GitHub la presenza degli asset immagine principali (logo e immagini di categorie).

## Attività indispensabili prima della pubblicazione ufficiale
1. **Amazon:** fornire credenziali Creators API e tracking ID effettivo; collaudare chiamate, cache, link, immagini e prezzi sul server. I risultati reali da 6 prodotti non sono attivi senza API.
2. **Storico prezzi offerte:** integrare Keepa o altra fonte affidabile e verificare davvero il riferimento storico prima di attribuire sconti ≥ 50% e risparmio ≥ 15 €. Il campo manuale di evidenza non equivale a verifica automatica.
3. **Archivio dati:** il gestionale usa un adapter Redis REST (`KV_REST_API_URL`/`KV_REST_API_TOKEN`), **non** il database MySQL/PostgreSQL SiteGround. Configurare Redis REST o implementare un adapter per database SiteGround; senza di esso statistiche e funzioni di scrittura admin non funzionano.
4. **Admin:** configurare un `ADMIN_DASHBOARD_TOKEN` lungo e casuale solo nell'ambiente server, testare accesso e funzioni. Valutare ulteriori misure di sicurezza per l'area riservata.
5. **Privacy:** completare dati identificativi del titolare e informative in base ai fornitori effettivamente attivati. Per AdSense nel SEE/UK/CH integrare una CMP certificata Google/TCF prima di attivare gli annunci; il banner custom non è una CMP certificata.
6. **Indicizzazione:** collegare dominio `cosa-regalo.it`, configurare `SITE_PUBLIC_URL=https://cosa-regalo.it` e, solo dopo collaudo e privacy completa, abilitare `SITE_INDEXABLE=true`; verificare sitemap, canonicals, metadati e dati strutturati.
7. **Piano editoriale:** il calendario è un brief precompilato, non un sistema autonomo di pubblicazione. Mancano scheduler, raccolta fonti e flusso di approvazione/pubblicazione.
8. **Preferiti:** il vecchio contatore sempre a zero è nascosto fino all'implementazione del salvataggio.
9. **Collaudo browser:** verificare visivamente desktop/tablet/mobile, caricamento degli asset, collegamenti, cookie, accessibilità, ricerca, admin, API, errori in console e performance dopo il redeploy SiteGround.
10. **Staging vs produzione:** controllare la risposta HTTP di `/robots.txt` e la presenza del meta `X-Robots-Tag: noindex` sul dominio temporaneo.

## Nota
Il sito non deve riportare prezzi o sconti presentati come verificati senza dati effettivi. Le funzioni non configurate non devono essere descritte come già operative.
